# 問題の追加・差し替えガイド

編集するのは **`/data/puzzles.ts` だけ**です。他のファイルは触りません。

---

## パターン1：文言だけ直す（いちばん多い）

問題文・ヒント・セリフの言い回しを直すだけなら、その文字列を書きかえて push するだけです。

**遊んでいる人の進捗は消えません。** 問題数も ID も変わらないためです。

---

## パターン2：問題を差し替える（3問のまま中身を変える）

該当する問題の `question` `visual` `answers` `keyword` などを丸ごと書きかえます。

このとき **`ending.explanation` も直してください。** 結果画面の
「なぜ『きく』？」の解説にキーワードが出てくるので、キーワードを変えると説明が合わなくなります。
忘れるとテストが落ちて教えてくれます。

古い進捗は問題数が同じなので引きつがれますが、
**中身が変わったなら `id` を新しくする**のが安全です（`stage2-q1` など）。
ヒント使用数が問題 ID ごとに記録されているためです。

---

## パターン3：問題を増やす・減らす

`puzzles` 配列に足す、または消します。

```ts
{
  id: "q4",                    // 他と重複させない
  label: "第4問",
  title: "画面に出る見出し",
  intro: "出題時のトヨタくんのセリフ",
  question: "問題文",
  visual: { kind: "fraction-list", items: [...] },  // 図。いらなければ省略
  placeholder: "ひらがなで答えてね",
  hints: ["ゆるいヒント", "ふつうのヒント", "ほぼ答え"],  // 必ず3つ
  answers: ["ひらがな", "漢字", "カタカナ"],              // 表記ゆれを列挙
  keyword: "キーワード",
  success: "正解時のセリフ",
  successSpeech: "正解時の読み上げ文（かなで）",
  speech: "問題の読み上げ文（かなで）",
}
```

増減したときは **`ending.explanation` に新しいキーワードの説明を足してください。**
そうしないとテストが落ちます（意図的にそうしてあります）。

進捗バーの段数や結果画面は、問題数から自動で計算されるので直す必要はありません。

> **前に遊んだ人の進捗は自動でリセットされます。**
> 問題数が変わると保存データと食いちがい、そのまま使うと
> 存在しない問題を指して画面が真っ白になるためです。黙って最初からになります。

---

## 図（visual）の種類

いまある3種類から選びます。いらなければ `visual` ごと省略できます。

```ts
// 漢字カード＋矢印
visual: { kind: "kanji-arrows", chars: ["花","加"], arrows: ["↑","←"] }

// 文字グリッド＋アイコン
visual: {
  kind: "cipher-grid",
  rows: ["めたがかば", "はねめばし"],
  iconHints: [{ icon: "🔍", label: "むしめがね" }],
}

// ことば＋分数
visual: {
  kind: "fraction-list",
  items: [{ word: "よこはま", frac: "3/4" }],
}
```

新しい形式の図が必要になったら、`/types/game.ts` の `PuzzleVisual` に
`kind` を1つ足し、`/components/puzzle-visual.tsx` に分岐を1つ書きます。

---

## 守ること（テストが自動で見張ります）

| ルール | 破るとどうなるか |
|---|---|
| `hints` は必ず3つ | テストが落ちる |
| `id` を重複させない | テストが落ちる |
| `answers` に漢字表記も入れる | 漢字で答えた子が不正解になる |
| `keyword` は自分の `answers` に含める | テストが落ちる |
| 読み上げ文はかなで書く | 「表」が「おもて」と読まれる。読みが割れる語はテストが検出 |
| キーワードを変えたら `ending.explanation` も直す | テストが落ちる |

## 作業の流れ

```bash
# 1. 編集する
#    /data/puzzles.ts

# 2. テストで不備がないか見る
npx vitest run

# 3. 実際に遊んで確かめる
npm run dev

# 4. push（GitHub Desktop でも可）
git add .
git commit -m "第2問を差し替え"
git push
```

**テストが落ちたまま push しても、Actions が止めるので公開はされません。**
壊れた問題が地域の人に届くことはない、と考えて大丈夫です。

## ステージを増やしたい場合

いまの `toyodaPuzzleSet` を丸ごとコピーして、新しい `id` の
`PuzzleSet` を作り、`puzzleSets` 配列に足します。

```ts
export const puzzleSets: PuzzleSet[] = [toyodaPuzzleSet, nextPuzzleSet];
```

ただし**現状は最初の1つだけを表示する作りです。**
ステージ選択画面と、遊ぶステージを切り替える仕組みが別途必要になります。
そこまでやるときは声をかけてください。

進捗の保存キーはステージ ID を含んでいるので、
ステージごとに独立して進捗が残ります。
